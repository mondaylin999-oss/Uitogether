# Deploying UITogether to Render

Three pieces go live:

| Piece    | Where                       | What it is                          |
| -------- | --------------------------- | ----------------------------------- |
| Frontend | Render **Static Site**      | `frontend/` — plain HTML/CSS/JS     |
| Backend  | Render **Web Service**      | `backend/` — Node + Express REST API|
| Database | **External MySQL** (Aiven)  | `database/` — schema + migrations   |

> **Why is the database not on Render?**
> Render's managed databases are PostgreSQL only. This app is built on MySQL
> (mysql2, MySQL triggers and views in `database/migrations/`), so the database
> is hosted on a free external MySQL provider and the backend connects to it
> over TLS. Everything else runs on Render.

---

## 1. Create the MySQL database

Either provider below has a free tier. Aiven is used in the examples.

**Aiven** — <https://console.aiven.io>

1. Create service → **MySQL** → **Free plan** → pick a region close to your
   Render region (the blueprint uses `singapore`).
2. Wait for the service to reach *Running*.
3. From the service overview copy the **Service URI**. It looks like:

   ```
   mysql://avnadmin:AVNS_xxxxxxxx@mysql-xxxxxxx-uitogether.a.aivencloud.com:12345/defaultdb?ssl-mode=REQUIRED
   ```

4. Change the database name at the end of the path from `defaultdb` to
   `uitogether_db`, keeping the `?ssl-mode=REQUIRED` query. Save this string —
   it is your `DATABASE_URL`.

*(Clever Cloud works the same way: create a MySQL add-on and build the URI from
the host, port, user, password and database name it shows you.)*

## 2. Load the schema

Run this **from your own machine**, once, before the first deploy. It creates
the database, applies every migration in `database/migrations/`, and seeds it.

```bash
cd backend && npm install
```

Then run the setup, passing the URI inline (nothing is written to disk):

```bash
DATABASE_URL="mysql://avnadmin:PASSWORD@HOST:PORT/uitogether_db?ssl-mode=REQUIRED" DB_SSL=true npm run db:setup
```

Verify it worked:

```bash
DATABASE_URL="mysql://avnadmin:PASSWORD@HOST:PORT/uitogether_db?ssl-mode=REQUIRED" DB_SSL=true npm run db:status
```

`db:setup` creates the database, migrates and seeds. Use `npm run db:migrate`
alone later when you add a migration file.

## 3. Deploy both Render services

The repository contains [`render.yaml`](render.yaml), so Render can create both
services in one step.

1. Go to <https://dashboard.render.com> → **New** → **Blueprint**.
2. Connect your GitHub account and pick this repository.
3. Render reads `render.yaml` and shows two services: `uitogether-api` and
   `uitogether-web`. It will prompt for the two values marked `sync: false`:

   | Service          | Variable       | Value                                                  |
   | ---------------- | -------------- | ------------------------------------------------------ |
   | `uitogether-api` | `DATABASE_URL` | the URI from step 1                                     |
   | `uitogether-web` | `API_BASE_URL` | `https://uitogether-api.onrender.com/api` (see step 4)  |

   `JWT_SECRET` is generated by Render automatically — you do not set it.

4. `API_BASE_URL` needs the backend's final URL, which you only know after the
   first deploy. Two options:
   - Put in the predicted URL (`https://<api service name>.onrender.com/api`) —
     Render derives it from the service name, so it is almost always correct; or
   - deploy, copy the real API URL from the `uitogether-api` page, set
     `API_BASE_URL` on `uitogether-web`, and redeploy the static site.

   **The `/api` suffix is required.**

5. Click **Apply**. Render builds the API (`npm ci`, `npm start`) and the static
   site (`scripts/build-frontend.sh`, which bakes `API_BASE_URL` into
   `frontend/config.js`).

## 4. Verify

```bash
curl https://uitogether-api.onrender.com/api/health
```

Expect `{"success":true,...}` with a healthy database check. Then open the
static site URL, register an account, and confirm no CORS errors appear in the
browser console.

## Environment variables reference

Set on **`uitogether-api`** (most are already in `render.yaml`):

| Variable               | Set by     | Notes                                          |
| ---------------------- | ---------- | ---------------------------------------------- |
| `DATABASE_URL`         | you        | Full MySQL URI, TLS required                   |
| `DB_SSL`               | blueprint  | `true` — hosted MySQL rejects plaintext        |
| `DB_SSL_CA`            | optional   | PEM bundle, only for a private CA              |
| `JWT_SECRET`           | Render     | Auto-generated; rotating it logs everyone out  |
| `CLIENT_URL`           | blueprint  | Wired to the static site's host, for CORS      |
| `NODE_ENV`, `PORT`     | Render     | `PORT` is injected; do not override it         |

Set on **`uitogether-web`**:

| Variable       | Notes                                                    |
| -------------- | -------------------------------------------------------- |
| `API_BASE_URL` | Backend origin **including `/api`**, no trailing slash    |

Individual `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` still
work and take precedence over `DATABASE_URL`, so you can override one field
without rewriting the URI. Leave them unset in production.

## Things to know about the free tier

- **The API sleeps after 15 minutes idle.** The first request afterwards takes
  ~30–50 seconds while the instance wakes. This is normal, not a bug.
- **Uploaded files do not survive a deploy.** `multer` writes to
  `backend/public/uploads/`, and Render's free filesystem is ephemeral — images
  uploaded to competitions or lost-and-found posts vanish on the next deploy or
  wake-up. For anything permanent, attach a Render **Disk** (paid) mounted at
  `backend/public/uploads`, or move uploads to an object store such as
  Cloudinary or S3.
- **Aiven's free MySQL also idles.** The very first request after a long quiet
  period can fail; the next one succeeds.

## Local development is unchanged

`frontend/config.js` still holds the `__API_BASE_URL__` placeholder in the
repository, so `api.js` falls back to `http://localhost:5050/api`. Only the
Render build rewrites it. Likewise, leaving `DATABASE_URL` unset keeps the
backend pointed at your local MySQL via the `DB_*` variables in `backend/.env`.
